## 排程与审核

1. 定位系列、课题、期号及角色，完整读取私有角色库中的唯一人格。
2. 从最终导演稿生成实际生产计划，审阅全部旁白、屏幕文字、动作、声音与片尾；单独绑定实际外部素材。详细人格和披露依据只保存在私有库。
3. 两项语义审核均通过后，检查计划及素材 SHA-256 绑定，再正式合成配音和渲染。
4. 按真实音频和词边界生成字幕、动作触发时间。复杂证明声明最小镜头时长和观察时间，音频比预算长时延长画面，绝不截断声音。
5. 检查渲染的真实媒体，而非仅检查预览图。检查全部台词、全部场景和动作数据；全片解码另记录技术覆盖。实际没有人工看完或听完时如实写未记录。

修文案、改动作、换人物或更新人格后，重新审核受影响的最终对象。不要因记录缺失向用户重新申请已授权的制作；由执行者完成实际审核并继续，不伪造 `passed`。

导演稿中的总时长只用于排练估算，不直接转成每镜硬性下限。先取得真实声音和词时间，按实际动作量分配观察窗口；长路径应有足够逐边演示时间，最后的静态结果不应为了凑预算停留数十秒。删掉无事件等待不能删引理、公式条件或必要的阅读时间。全片检查需分别统计声音停顿与无画面事件的静止，两者不能混为一谈。

## 并行制作与第一期优先

多期可以同时进行，但每期独立保存生产计划、声音缓存、字幕、分段编码、尝试收据和最终影片。不能让两个进程写同一缓存、时间轴或最终文件。共享 Java 后端由一个任务协调构建，各生产进程使用固定的引擎和 worker；后续代码更新不改变已经启动的运行。

冲突时先保证第一期：优先修复第一期的阻断问题，给它保留编码资源，后两期可继续做数学数据、配音和预览；后两期的工作不能覆盖第一期稿源或导致其构建/渲染失效。资源允许时可以同时编码，记录实际运行而非声称三期都在渲染。
