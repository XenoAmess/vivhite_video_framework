# 完整人格驱动的视频创作与文案审核规约

本规约适用于包含主人公的视频选题、文案、导演稿、分镜、字幕、配音及后续改稿。它是项目必做流程；执行入口见根目录 [AGENTS.md](../AGENTS.md)。

## 仓库与稿源

- 视频工程、通用流程、导演稿和非敏感制作记录保存在本公开仓库。
- 主人公资料独立保存在 [vivhite_characters 私有仓库](https://github.com/XenoAmess/vivhite_characters)。每位主人公一个目录，`characters/<id>/persona.md` 是该角色唯一的完整人格稿源。
- 人格不拆成隐私版、公开版或供创作使用的删减版。保留同一文档内的 `[可呈现]`、`[不强调]`、`[禁止展示]` 标识。
- 私有库同时保存角色素材、设定来源和详细审核依据。公开工程只引用角色 ID、文件指纹、角色库提交与审核状态，不复制人格正文、隐私摘录或敏感审核原因。
- 本地默认使用本工程同级的 `vivhite_characters`；可通过 `VIVHITE_CHARACTERS_HOME` 或检查脚本的 `--characters-home` 指定已有克隆。不把私有库作为公开仓库的子模块或子目录。

以上限制针对人格档案及详细审阅依据。根据完整人格创作、符合展示标识的台词和人物表现可以成为公开作品；这不等于在公开库另建一份人格说明或删减档案。

系列与课题使用 [series](../series/README.md) 组织：`series/<系列>/<课题>/episodes/<期>/`。每期 `episode.json` 声明稳定 ID、`cast` 角色 ID 和导演稿入口；课题清单负责各期之间的关系。数学教育／逆序数课题当前包含 `vivhite`，展示名由私有角色库解析，不在公开工程维护第二份人格。

## 创作前必须自动执行

1. 阅读本规约、系列与课题说明、当前期 `episode.json`。发现新人物时先定位其完整档案，不能用名字或记忆补全。
2. 用 `character_review.py context` 定位完整人格文件，取得角色库提交及完整文件 SHA-256；**创作者接着必须完整读取这些文件的正文**。脚本读字节、计算哈希或打印路径不算大模型已经通读。
3. 全部标识和后台背景一起进入当前创作上下文，不能先删掉敏感段落，再把删减结果交给写作者。后台知情用于理解角色，不表示可以写进台词。
4. 完整人格缺失、角色 ID 不存在、人格有未提交修改时停止依赖它的创作步骤，说明缺少哪个档案或版本；不静默降级到无人格创作。
5. 不将人格复制进公开提示词、原始模型返回、日志、测试快照或导演稿。需调用外部模型时，使用已获用户授权的服务，提示词和可能含后台信息的返回保存在私有位置，完成审核后才导出可发布的文案。不得把人格送到搜索引擎。

```powershell
# 使用制作器已有的 Python 环境；可指定其他 Python 3.12+
$episode = 'series/math-education/inversion-count/episodes/02-rectangle-proof/episode.json'
video-maker/.venv/Scripts/python.exe scripts/character_review.py context --episode $episode
# 按输出的 personaFile，使用读取工具完整阅读全文后开始创作。
```

脚本核对人格的当前字节与所记录角色库 Git 提交一致；先在私有库提交人格更改，再使用新版本创作。它不自动拉取或覆盖已有克隆，不自动改变仓库可见性。

## 写稿与修改

人格体现在主动性、语气、兴趣、反应、操作、失误和恢复方式中；不要求每期报出人物背景。`[不强调]` 允许理解其影响，但不能主动突出、反复揭露或做成固定笑点；`[禁止展示]` 不得直接、间接或组合披露。角色的临时出戏、其他人的台词和画面道具不能绕过标识。

数学正确性、风格相似性和人格表现分别检查。不能为了表现角色失误而让错误数学成为最终结论；不能为了让稿子通过而删掉人格背景或改变隐私标识。用户更新设定时以新设定为准，并重新审核受影响的稿件。

## 成稿后追加两项独立语义审核

审核必须覆盖每一镜的全部旁白、对白、屏幕文字、字幕、动作、道具、人物素材可见文字、声音和片尾，以及跨镜头拼合的信息。逐句、逐镜审阅，关键词扫描只可辅助。

| 审核项 | 必须判断 | 通过条件 |
| --- | --- | --- |
| 人格一致性 `personalityConsistency` | 语气、动机、能力表现、舞台状态及失误是否符合完整人格；是否擅自增加背景或突出不强调特质 | 全部片段符合设定，发现的问题已修订复审 |
| 信息披露 `informationDisclosure` | 是否直接、同义改写、通过画面/声音、他人台词、隐喻或组合线索暴露禁止展示的信息 | 无禁止披露内容，也未用秘密解释台词、习惯、情绪或失误 |

两项各自记录 `passed` 或 `failed`，不能互相抵消。实际审阅者填写结论与依据；脚本不得通过关键词、哈希匹配或模型自评字段自动宣布语义通过。助手完成的审核标为 `assistant-semantic-review`，人工审核标为 `human-semantic-review`，不把助手审核描述为人工验收。

发现问题：在私有库记录片段、原因与修订建议，修改文案，再对最终全文复审。公开评论、issue、提交信息或终端错误不得引用具体秘密。

## 审核记录与版本绑定

详细审核存入私有库：

```text
reviews/<series>/<topic>/<episode>/<document-sha256>.json
```

字段约定见私有库 `docs/authoring-and-review.md` 和本工程 [检查脚本](../scripts/character_review.py)。记录包含正文 SHA-256、所有角色的完整人格 SHA-256 与 Git 提交、审阅方式、覆盖范围、逐镜依据和两个结论。不要只写一句“没有问题”而没有实际检查对象。

审核通过后，用 `receipt` 命令生成本期 `reviews/<document-sha256>.json`。这个公开收据是版本与结论记录，**不是公开人格档案**。脚本只导出预定字段，不导出私有依据；不能把私有 JSON 整体复制过来。详细记录的机器入口必须为 JSON，Markdown 可作为附加依据。

```powershell
video-maker/.venv/Scripts/python.exe scripts/character_review.py receipt --episode $episode
video-maker/.venv/Scripts/python.exe scripts/character_review.py check --episode $episode
```

默认绑定 `episode.json` 指向的导演稿；审核最终制作计划时使用 `--document <实际计划.json>`，其哈希另存一份审核记录。对计划之外传入的人物图片/视频、音乐等，使用可重复的 `--asset <实际文件>`，在 context、receipt、check 三步使用同一组素材；收据只保存素材哈希，不导出路径或内容。制作脚本自动传入实际 Presenter。

文案、人格或外部素材任一字节变化，旧记录失效；重新通读完整人格、审核最终稿和素材并生成新收据。改标题、字幕、动作说明或片尾同样适用，不能只复用先前正文的通过结论。

## 正式制作与验收

- 先通过人格和披露审核，再把对应最终计划送入正式配音与渲染。技术预览可先行，但不能因此记录成片已通过审核。
- `scripts/produce-puzzle-video.ps1` 会在正式 `produce` 前对本次生成的实际计划运行检查；新增制作入口须沿用这个步骤。第一次审核该计划时，检查会保留计划并指出需要的哈希记录，完成实际语义审核后再执行。
- 根目录 `AGENTS.md` 对会话创作强制以上步骤。当前底层 Java `prepare/generate/produce` 命令尚未加载人物仓库或内置语义审核，直接调用不会自动完成人格创作；包含人物的正式任务必须按本规约读取完整人格并使用检查入口。不得把底层命令的成功当作本流程已通过。
- 生成器新增台词、字幕、片尾、声音或素材后，重新检查新增的最终可见/可听内容；视频输出另需做数学、风格、音画同步和技术检查。审核文案通过不等于已完整观看成片。
- 第一期现有成片是本规约建立前的历史交付，保持原样，不补写“已通过人格审核”。以后改稿或重新制作同样需要审核。

私有库推送前须确认 GitHub 可见性仍为私有；公开库提交前检查差异，确保没有完整人格、敏感摘录、私有依据或模型原始返回。两个仓库分别提交、推送，不把同级目录混进一次提交。

版本检查工具的边界测试：

```powershell
video-maker/.venv/Scripts/python.exe -m unittest discover -s scripts -p test_character_review.py -v
```

覆盖缺失/失败审核、写稿前人格定位、文案变化、人格变化、外部素材替换、全镜头要求、路径越界、审核提交与人格源版本分离，以及公开收据不带私有正文/证据。
