## 本次重写

旧稿沿知识点顺序讲授搜索算法、复原方法和不变量，缺少目标片不断构造、使用同一件工具的过程。本次改为：

1. 开场实际使用判别器，演示原例与不可达反例，承诺稍后构造。
2. 四格滑动产生循环次序，两个12态环展示可达类别；行末成对归位补充复原策略。
3. 展开同一棋盘，连接到排序参照，用交叉线对解释逆序；0保留为独立对象。
4. 展示抽象对换及五次相邻对换，再回到合法滑动的奇偶翻转。
5. 加入空格颜色，用两个开关同时翻转构造不变量，区分必要性与有条件的充分性。
6. 装回开场装置，实算原例、目标和反例；接着构造状态图，按验证数据播放14步最短路线。
7. 一次简短收束及内容/表达参考署名。

公式、读数、棋盘和连线承担推理；条件、复杂度、适用范围进入次层注释。没有把样式相似度简化为配色、规则ID或字幕速度。人物先使用原图与提示线，承担注意力引导，后续再替换为可表演的形象。

## 真实制作链路

Java先验证状态序列、图形类型和字段。Python Edge worker在线合成39段声音，保留实际音频与词边界。Java消费按真实音长生成的时间轴，通过Java2D逐帧画数学对象，管道送入FFmpeg分段编码；最后拼接、归一化响度并导出带画面字幕的成片和外置SRT。

本次使用RTX 3080的NVENC；CPU编码器也可选。人物图为用户指定的 `718c36bc01a173d0c42c0d1131f67e31055244c7.jpg`，原文件未修改。素材层也已实测加载WebM视频，但没有直接集成Live2D模型、实时口型或表情。

配音使用联网服务，不是本地语音模型。独立API模型分析/导演入口没有在此制作中使用；本例全文、图形编排与修订由会话助手完成，本地代码执行数学、时间和媒体计算。

首次使用参考项目版本7.2.8时服务返回403，改用上游已修复的7.3.1后完成实际晓晓合成。保留锁定依赖和缓存；未静默切换到其他声音。

## 重做

安装配音环境后，在仓库根目录执行：

```powershell
.\scripts\produce-puzzle-video.ps1 -Build -VideoCodec h264_nvenc
```

本机已有全部配音，离线复用当前缓存：

```powershell
.\scripts\produce-puzzle-video.ps1 -VideoCodec h264_nvenc -OfflineTts `
  -TtsCacheDirectory D:/workspace/vivhite-analysis-output/puzzle-restyle/production-v2/tts-cache
```

改变 `-Voice`、`-Rate`、`-Presenter` 后，缓存键会改变；缺少新声音缓存时不能使用离线模式。修改文案应先改案例适配器，重新导出计划和实测导演稿。其他项目可以直接消费自己的 `vivhite-production-1` 计划；当前图形类型集合见制作器文档。
