# 通用证明动画场景

`vivhite-production-1` 的 `beat.view = "proof"` 提供图、合法滑动、抽象置换、分阶段表格和矩阵推导。原有八种视图仍可使用。完整制作入口、配音、人物及审核见 [production.md](production.md)。

这一后端沿用 Java 2D 和 FFmpeg，不增加第三方依赖。它把一次合法滑动执行为唯一空格与相邻牌的交换，把抽象置换执行为实际标号的运动；两者分别标出图上操作和代数层。矩阵和证明表使用逐阶段行替换及高亮，不会从公式字符串自动推导数学结果。

## JSON 契约

下面是一圈四步滑动。空格回根后，另外三块牌实际发生三轮换。

```json
{
  "id": "square-loop",
  "chapter": "局部工具",
  "heading": "绕一圈，再回到这里",
  "seriesLabel": "逆序数 · 矩形棋盘",
  "narration": "空格沿这四条边绕一圈。看另外三块牌，它们接力换了位置。",
  "view": "proof",
  "action": "空格逐边滑动；回根后保持三轮换结果供比较。",
  "formula": "合法闭路 → 另外三块牌的三轮换",
  "proof": {
    "mode": "graph",
    "nodes": [
      {"id": "a", "label": "a", "x": 0, "y": 0},
      {"id": "b", "label": "b", "x": 1, "y": 0},
      {"id": "c", "label": "c", "x": 1, "y": 1},
      {"id": "d", "label": "d", "x": 0, "y": 1}
    ],
    "edges": [["a", "b"], ["b", "c"], ["c", "d"], ["d", "a"]],
    "root": "a",
    "blank": "a",
    "initialTokens": {"a": "0", "b": "1", "c": "2", "d": "3"},
    "rows": ["圈内是牌；圈下是固定位置。"],
    "steps": [
      {
        "text": "空格逐边绕一圈",
        "cue": "空格沿这四条边",
        "focus": ["a", "b", "c", "d"],
        "walk": ["a", "b", "c", "d", "a"]
      },
      {
        "text": "比较三块牌的结果",
        "cue": "看另外三块牌",
        "focus": ["b", "c", "d"],
        "rows": ["空格回到 a。", "b、c、d 的三块牌发生三轮换。"]
      }
    ]
  }
}
```

`proof.mode` 是 `graph`、`permutation`、`table` 或 `matrix`。前两种必须有节点；纯表格或矩阵可以没有节点。节点 `id` 唯一，`label` 是固定位置名，`x/y` 是 `[0,1]` 内的归一化坐标，位置不得完全重合。最多 40 个节点；更大的推导拆成多个镜头。

`initialTokens` 按节点 ID 指定牌面。提供时必须覆盖全部节点且牌面唯一；省略时使用节点标签，空格位置使用 `0`。`blank` 指定最初空格位置，必须对应唯一的 `0`；没有 `blank` 时，数字 `0` 可以作为普通代数标号。`root` 只标记固定根，不代表空格一直位于该处。节点及牌面最多 10 个 Unicode 字符，实际画面还要求牌面在圆牌内可读，长解释放入 `rows`。

可选 `proof.pointer: true` 让人物的指示线指向本阶段 `focus` 的重心；单节点聚焦用于准确指点或可恢复的指错再纠正。默认不画这条线。

## 动作与时间

`steps` 含 1 至 120 个阶段。阶段是有顺序的增量动作：牌面排列、已添加的边和显示行会传给下一阶段。`text` 和 `focus` 只属于当前阶段。

| 字段 | 语义 |
| --- | --- |
| `text` | 当前阶段说明，最多 50 个 Unicode 字符；建议一句短话。 |
| `cue` | 本镜旁白中的原文短语，由配音词级时间决定阶段开始；短语必须出现在旁白中。 |
| `focus` | 本阶段强调的节点 ID 列表。已有边的两端都在其中时强调该边。 |
| `rows` | 替换全部当前显示行；省略时沿用，空数组清空。 |
| `highlightRow` | 当前行的从零开始索引；省略为无高亮。 |
| `walk` | 包含起点的空格路径。起点必须是当前空格，每一跳必须沿现有边。 |
| `cycles` | 抽象位置循环列表；每个循环中，第 i 个位置的牌移到下一个位置。 |
| `addEdges` | 本阶段开始添加的边，端点必须是已声明节点；之后保留。 |

同阶段不能兼有 `walk` 和 `cycles`。同阶段多个循环必须互不相交；有重叠的置换复合拆成多个阶段，按执行次序填写。若公式采用右到左复合，先写右边置换的阶段。此规则避免把代数置换误当成一次合法滑动。

`walk` 含 2 至 500 个路径位置。系统预先执行全部交换，验证每一步并保存真实牌面；动画在阶段前 75% 按步数分配时间，每小步末尾 18% 保持刚完成的局面，整个阶段后 25% 保持最终结果。一个口播触发可以覆盖多步滑动，路径中的牌不会瞬移到最终快照。

实测时间轴 `timing.visualTimes` 与所有 `steps` 一一对应，记录开始秒数。阶段末端是下一阶段开始或本镜结束。首触发前保持初始布局。缺少实测时间的技术预览按进度均匀分配阶段，不代表正式音画同步验收。为了观察和操作而预留的无旁白区间由制作计划的时长约束与时间轴共同决定。

正式 worker 在每对真实词锚点之间先按操作量预留时间（每条合法移动至少0.30秒、抽象循环至少0.8秒），再分配余量，避免把120步的共轭路径和一行结果等时播放。`minDurationSeconds` 是确有操作/阅读需求时的下限；`tailSeconds` 是口播结束后的观察窗口，默认0.42秒。总帧数取真实口播加尾段与明确下限的较大者，并对齐视频帧；不能截断配音。原导演稿预算应留作元数据，不能盲目变成硬下限后用静帧补足。

`preview` 除每镜中间图外，还导出每个证明阶段落稳图及 `preview-manifest.json`，渲染前即可检查全部表格和标签能否放下。`review_film.py` 则从实际编码的 MP4 中提取每个阶段和每条合法路径子步的结果，两类证据不能混用。

## 画面与边界

图和置换使用左图右解释；没有解释行时扩大图区域。固定位置标签在圆牌下方，移动牌面在圆内。空格用虚线圈表示，根用外圈标记。人物保留独立的图片/预渲染视频图层，字幕、底部总公式和本场景互不覆盖。

- `graph/permutation`：每阶段最多 5 行，每行最多 34 个 Unicode 字符。
- `table/matrix`：每阶段最多 7 行，每行最多 68 个 Unicode 字符。
- 字符数是数据上限。字体和换行后仍放不下的表格会报错，必须拆阶段，不能无限缩小字体。
- 长证明表、九步恒等式和完整有限分类表应按正在使用的行逐步展示；不能把整张附录缩成一块图片。
- `matrix` 支持矩阵行、公式变换行及当前行高亮，数学变换的正确性由作者及独立验证程序保证。

场景解析、所有合法滑动及最终排列在渲染前预计算；静态图、位置标签和本阶段文字只在阶段变化时重绘。只缓存当前静态画面，避免长片每阶段保留整张 1080p 图片。移动牌保持按帧计算，时间和输出均为确定性。

中文主字体缺少数学符号时，文字层按字符回退到已安装的数学/符号字体，并缓存文字布局。缺少所有可用字形时直接报错，避免把上标负号等符号悄悄画成方框。静态场景在实际输出分辨率缓存，公式文字不会先缩成 720p 再放大。

Java 测试覆盖闭路的真实三轮换、非法边/错误空格拒绝、增量加耳、置换组合、未知节点/坐标/重复空格拒绝、表格溢出、词触发前保持和渲染确定性。数学普遍结论不能仅由这些有限测试证明，仍需对应完整证明及证书。
